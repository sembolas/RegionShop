# RegionShop — Веб-приложение для автоматизации заказов

![Python](https://img.shields.io/badge/python-3.12-blue)
![Django](https://img.shields.io/badge/django-5-green)
![React](https://img.shields.io/badge/react-18-cyan)
![PostgreSQL](https://img.shields.io/badge/postgresql-15-blueviolet)
![Docker](https://img.shields.io/badge/docker-compose-orange)

Веб-приложение для автоматизации приёма и обработки заказов компании «Регион Инвест». Позволяет клиентам выбирать товары в каталоге, оформлять заказы онлайн, а менеджерам — управлять заказами через единую панель с отслеживанием статусов. Интегрируется с существующей системой 1С.

## 🎯 Функциональность

### 👤 Клиентская часть
- **Регистрация и авторизация** по JWT токенам
- **Каталог товаров** с фильтрацией, поиском и пагинацией
- **Карточка товара** с детальной информацией и добавлением в корзину
- **Управление корзиной** (изменение количества, удаление позиций)
- **Оформление заказа** с указанием контактных данных
- **Личный кабинет**:
  - Профиль пользователя (ФИО, телефон, компания, ИНН)
  - История заказов с фильтрацией по статусу
  - Детализация заказа с позициями и ценами
  - Отслеживание статуса заказа

### 👨‍💼 Панель менеджера
- **Дашборд заказов** с фильтрами по статусу и дате
- **Детальная карточка заказа** с составом и данными клиента
- **Управление статусами** заказов (новый → в обработке → выполнен)
- **История обработки** каждого заказа
- **Каталог товаров** и управление остатками
- **Привязка клиентов** к контрагентам в системе 1С

### 👑 Административная панель
- Полный доступ через стандартную Django Admin панель (`/admin/`)
- Управление пользователями, ролями и настройками

## 🔌 Интеграция с 1С

Каталог товаров синхронизируется из системы 1С через OData протокол. Решение использует кэширование для повышения производительности.

### 📋 Схема синхронизации

1. **Frontend** запрашивает товары через API Django
2. **Django** проверяет актуальность кэша в PostgreSQL
3. **Если кэш устарел** → запрос к 1С через OData (`onec-odata`)
4. **1С** возвращает JSON с товарами, ценами и остатками
5. **Django** обновляет кэш в PostgreSQL и возвращает данные
6. **React** отображает каталог товаров

### 🔄 Процесс заказа

1. Клиент оформляет заказ через интерфейс
2. Backend проверяет доступность остатков
3. Создаётся запись заказа в PostgreSQL
4. Заказ ставится в очередь на выгрузку в 1С
5. В 1С создаётся документ "Заказ клиента"
6. Статус заказа обновляется в обеих системах

### 👥 Привязка клиентов

- При регистрации клиент связывается с контрагентом в 1С по ИНН/телефону
- Или менеджер выполняет привязку вручную через панель управления
- В профиле клиента хранится `onec_ref_key` (GUID контрагента)
- Только менеджеры могут изменять привязки к 1С

## 👥 Система ролей

| Роль | Права доступа |
|------|---------------|
| **Клиент** | Каталог, корзина, только свои заказы, личный профиль |
| **Менеджер** | Все заказы, изменение статусов, управление каталогом, привязка клиентов к 1С |
| **Администратор** | Полный доступ через Django Admin |

## 🚀 Быстрый старт

### Локальная разработка

#### Backend

```bash
cd backend
python -m venv venv

# Запуск сервера разработки
python manage.py runserver
```

API будет доступно по адресу: http://localhost:8000/api/

#### Frontend

```bash
cd frontend
npm install
npm run dev
```

Приложение откроется по адресу: http://localhost:5173/

## 📚 API документация

### 🔐 Аутентификация и профиль

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| POST | `/api/auth/register/` | Регистрация нового клиента |
| POST | `/api/auth/login/` | Авторизация (получение access/refresh токенов) |
| POST | `/api/auth/refresh/` | Обновление access токена |
| POST | `/api/auth/logout/` | Выход из системы (blacklist refresh токена) |
| GET | `/api/auth/me/` | Получение данных текущего пользователя |
| PATCH | `/api/auth/me/` | Обновление профиля пользователя |

### 🛍️ Каталог и заказы

| Метод | Эндпоинт | Описание | Доступ |
|-------|----------|----------|--------|
| GET | `/api/products/` | Получение каталога товаров | Все |
| GET | `/api/products/{slug}/` | Карточка товара | Все |
| GET | `/api/categories/` | Список категорий | Все |
| POST | `/api/orders/` | Создание нового заказа | Клиенты |
| GET | `/api/orders/my/` | История заказов пользователя | Клиенты |
| GET | `/api/orders/{id}/` | Детализация заказа | Клиенты/Менеджеры |
| PATCH | `/api/orders/{id}/` | Изменение статуса заказа | Менеджеры |

## ⚙️ Конфигурация

### Переменные окружения

Создайте файл `.env` в корне проекта:

```env
# Django
SECRET_KEY=your-secret-key-here
DEBUG=False
ALLOWED_HOSTS=localhost,127.0.0.1

# База данных
DATABASE_URL=postgres://user:password@db:5432/regionshop

# CORS
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://localhost:3000

# 1С интеграция
ONEC_BASE_URL=http://1c-server/base
ONEC_USER=username
ONEC_PASSWORD=password

# JWT
JWT_ACCESS_LIFETIME=60  # Минуты
JWT_REFRESH_LIFETIME=1440  # Минуты (24 часа)

# Redis (опционально для кэширования)
REDIS_URL=redis://redis:6379/0
```

### Настройка 1С

1. Включите публикацию OData в конфигурации 1С
2. Настройте доступ по HTTP Basic Auth
3. Укажите URL, логин и пароль в переменных окружения

## 🔐 Безопасность

- **Аутентификация**: JWT с access/refresh токенами
- **Авторизация**: RBAC (ролевая модель) на уровне Django
- **CORS**: настроены разрешённые домены
- **CSRF**: защита для сессионных запросов
- **Валидация данных**: Django Forms и Serializers
- **SQL-инъекции**: ORM Django защищает от инъекций

## 📈 Бизнес-логика заказов

При оформлении заказа выполняются следующие проверки:

1. **Перерасчёт цен** — система не доверяет суммам с клиента
2. **Проверка остатков** — товары доступны в нужном количестве
3. **Атомарная транзакция** — списание остатков в рамках одной транзакции
4. **Фиксация цен** — цена в `OrderItem.price` сохраняется на момент заказа
5. **Выгрузка в 1С** — создание документа "Заказ клиента" в системе 1С
