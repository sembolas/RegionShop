Веб-приложение для автоматизации приёма и обработки заказов фирмы «Регион Инвест». Клиент выбирает товары в каталоге, добавляет в корзину и оформляет заказ онлайн; менеджеры получают заказы в единой панели и отслеживают статусы (новый → в обработке → выполнен). Товары берутся из существующей базы 1С. Есть авторизация и личный кабинет клиента.

Стек
Backend: Python 3.12, Django 5, Django REST Framework

Frontend: React (Vite), React Router, Axios, Zustand

БД: PostgreSQL

Аутентификация: JWT (djangorestframework-simplejwt)

Интеграция с 1С: OData (HTTP), библиотека onec-odata, кэширование каталога в PostgreSQL

Развёртывание: Docker, Nginx, Gunicorn

Функциональность
Клиент:

регистрация и вход;

каталог товаров с фильтрами и поиском;

карточка товара, добавление в корзину;

управление корзиной (количество, удаление);

оформление заказа с контактными данными;

личный кабинет: профиль, история заказов, отслеживание статуса.

Менеджер:

панель со списком заказов и фильтрами по статусу и дате;

карточка заказа с составом и данными клиента;

смена статуса и история обработки;

управление каталогом и остатками;

привязка клиентов к контрагентам 1С.

Администратор:

полный доступ через админ-панель Django (/admin/).

Роли
Роль	Что видит
Клиент	Каталог, корзина, только свои заказы, свой профиль
Менеджер	Все заказы, смена статусов, каталог, привязка клиентов к 1С
Администратор	Полный доступ
Для разграничения используется стандартная модель User + профиль ClientProfile с полем onec_ref_key (GUID контрагента в 1С).

Интеграция с 1С
Каталог товаров не хранится в RegionShop как первичный источник. Django синхронизирует справочник «Товары» и цены/остатки из 1С через OData и кэширует их в PostgreSQL для быстрой отдачи витрины.

Схема запроса товаров:

Django получает запрос от React на список товаров.

Django через библиотеку onec-odata обращается к 1С по HTTP.

1С возвращает JSON с товарами, ценами и остатками.

Django кэширует ответ в PostgreSQL.

React получает данные и рисует витрину.

Синхронизация: по расписанию (Celery beat или cron) каждые N минут — обновление кэша товаров и остатков. При оформлении заказа данные передаются обратно в 1С (создание документа «Заказ клиента») или выгружаются отдельной задачей.

Привязка клиента к 1С: при регистрации клиент связывается с контрагентом по ИНН/телефону или вручную менеджером. Поле onec_ref_key в ClientProfile хранит GUID контрагента. Привязку подтверждает backend или менеджер — клиент не может выбрать чужую компанию.

Быстрый старт
Backend
bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# настройка БД и 1С в config/settings.py или через .env
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
API будет доступно на http://localhost:8000/api/.

Frontend
bash
cd frontend
npm install
npm run dev
Приложение откроется на http://localhost:5173/.

Бизнес-логика оформления заказа
При POST /api/orders/ backend:

пересчитывает цены заново (не доверяет суммам с клиента);

проверяет остатки на складе;

списывает остатки в рамках transaction.atomic;

фиксирует цену в OrderItem.price на момент заказа;

передаёт заказ в 1С (создание документа «Заказ клиента») или ставит в очередь на выгрузку.

Личный кабинет
Профиль — ФИО, телефон, компания, ИНН; данные могут подтягиваться из контрагента 1С.

История заказов — таблица: номер, дата, сумма, статус; фильтр по статусу.

Детали заказа — позиции, цены на момент заказа, текущий статус и история переходов.

Защита маршрутов в React — компонент <PrivateRoute>, проверяющий access-токен и редиректящий на /login.
